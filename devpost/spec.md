# Mydobby — Technical Specification

## How This Works, In Plain Language
Mydobby is a full-stack Next.js web application built around an emotional, low-friction user loop:
1. The user dumps raw thoughts and selects their bandwidth.
2. The client calls a server-side route `/api/plan`, which queries Groq AI or falls back to an Ikigai heuristics engine to isolate one concrete action.
3. The user takes the action and marks it done.
4. The client calls `/api/letter` to generate an empathetic future-self letter that honors actual completed actions.
5. Three.js renders an interactive, procedurally generated 3D animal companion that "delivers" the letter.
6. The client syncs data via the Supabase JavaScript SDK to PostgreSQL tables protected by Row Level Security (RLS) linked to `auth.users.id`.

## The Core Journey Through the System
- **Mind Dump & Capacity Selection**: User inputs are captured in React state (`mindDump`, `time`, `energy`, `goal`, `messenger`).
- **Plan Generation**: When advancing to the Step screen, `POST /api/plan` evaluates load and returns `{ nextStep, why, priority, currentLoad, plan }`.
- **Action Resolution**: User clicks "I did it". `addHistoryItem` fires `canvas-confetti`, appends to React state, and inserts into `public.check_ins`.
- **Letter Generation**: User clicks "Write milestone letter". `POST /api/letter` generates the letter JSON, animates the wax seal, and inserts into `public.letters`.
- **Cloud Sync**: `loadUserDataFromSupabase` queries `profiles`, `check_ins`, and `letters` on login or refresh.

## Stack
- **Framework**: Next.js 16 (App Router, standalone output, React 19).
- **Styling**: Tailwind CSS v4 with `@import "tailwindcss";` and custom keyframe animations.
- **3D Graphics**: Three.js (`three` + `@types/three`) with custom procedural low-poly avatars (Owl, Raven, Phoenix, Fox, Hummingbird), dynamic lighting, and orbit damping.
- **AI Engine**: Server-side Next.js route handlers (`/api/plan`, `/api/letter`) querying Groq Cloud API with OpenAI-compatible chat completions and structured JSON schema parsing.
- **Database & Auth**: Supabase Auth (email/password) + Supabase PostgreSQL with Row Level Security (RLS) enabled on all tables.
- **Delight Effects**: `canvas-confetti` for celebratory tactile micro-feedback.

## Where It Runs and How Someone Tries It
- **Local Dev Server**: `npm run dev` (starts on `http://0.0.0.0:3000`).
- **Build / Production**: `npm run build && npm run start`.
- **Shell Runner**: `./run.sh` automated test and startup script.
- **Environment Variables**:
  - `GROQ_API_KEY`: Optional Groq API key.
  - `NEXT_PUBLIC_SUPABASE_URL`: Supabase project URL.
  - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: Supabase anon/publishable key.

## Data Model (PostgreSQL & Supabase RLS)

### `public.profiles`
- `id`: UUID (Primary Key, references `auth.users(id) ON DELETE CASCADE`)
- `email`: TEXT
- `mind_dump`: TEXT
- `time_budget`: TEXT
- `energy_level`: TEXT
- `goal`: TEXT
- `messenger`: TEXT
- `updated_at`: TIMESTAMPTZ

### `public.check_ins`
- `id`: BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
- `user_id`: UUID (references `auth.users(id) ON DELETE CASCADE`)
- `title`: TEXT
- `status`: TEXT ('done', 'partial', 'changed', 'skipped')
- `date`: TEXT
- `created_at`: TIMESTAMPTZ DEFAULT NOW()

### `public.letters`
- `id`: UUID DEFAULT gen_random_uuid() PRIMARY KEY
- `user_id`: UUID (references `auth.users(id) ON DELETE CASCADE`)
- `type`: TEXT ('milestone', 'monthly')
- `title`: TEXT
- `body`: TEXT
- `summary`: TEXT
- `messenger`: TEXT
- `created_at`: TIMESTAMPTZ DEFAULT NOW()

## Important Failure Modes & Fallbacks
1. **Groq API down or key missing**: Server routes immediately invoke deterministic Ikigai heuristics without bubbling 500 errors to the client.
2. **Supabase offline or missing tables**: App surfaces clear error codes in a dismissible banner while allowing local progress to continue uninterrupted in Guest Mode.
3. **WebGL / 3D Canvas unsupported**: Component catches initialization errors and gracefully displays a styled 2D messenger emblem.

## Decisions & Open Issues
- **Single Page App State Machine**: Chose view-based navigation (`screen` state) over Next.js sub-routes to keep screen transitions seamless and preserve 3D canvas context between steps.
- **Guest Mode by Default**: No barrier to entry; users can experience immediate relief before deciding to create an account.
